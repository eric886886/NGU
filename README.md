# NaxaStudio 动态首页（Motion 版）

英文版 `index.html`，中文版 `zh.html`。两个版本共用同一套样式和播放引擎，右上角的 EN / 中文 互相链接。

把 naxastudio.com 首页的全部内容重新设计成一部自动播放的"短片"：打开网页就从头开始播放，依次展示每一部分内容，约 2 分 53 秒。

短片放完后，页面自己顺滑地往下滚，接着展示其他页面的内容，按一个完整的故事排：关于（我们为什么做这件事）→ AI 方案（我们用什么帮你）→ 起步 AI 方案（小团队从哪开始）→ Demo（先看看实际效果）→ 案例（真实的问题怎么被解决）→ AI 业务诊断（第一步怎么做）→ 联系（现在就开始），最后是页脚。短片最后一句是"把想法变成行动"，紧接着的"关于"开头就是"陪你借助 AI 的力量，把想法变成现实"，Logo 的粒子也直接从短片结尾移过来，中间不断开。整页从头到尾不用点任何东西，英文版约 11 分钟，中文版约 10 分钟。随时可以自己上下滑动浏览。

## 创意

官网 Logo 本身就讲了一个故事：一串散开的小点（想法）汇成波浪，组成 N，最后变成向上的箭头（行动），对应口号 "Turn ideas into action"。

整部短片由一群粒子贯穿始终。所有粒子都从 Logo 图片里采样，每个粒子都保留了 Logo 上对应位置的颜色。每一章，它们变成一种不同的形态：

| 章节 | 版式 | 粒子形态 |
| --- | --- | --- |
| Intro | 品牌名、纳想 | 一个"想法"光点炸开，拼成 Logo |
| 01 首屏 | 粗黑体标题，配一行衬线斜体 "It’s not as hard as you think."；三句短语依次弹出；介绍段落逐词点亮 | Logo 移到右侧，一道光从左到右扫过 |
| 02 执行流程 | 一个超大单词以"解码"效果在 Capture → Organize → Build → Execute → Improve 之间切换，下方是五个节点和 Idea → Action 进度线 | 粒子流穿过五个节点：散乱 → 收拢 → 分成三条 → 拼成块 → 汇成一束 |
| 03 痛点 | 六条痛点大小不一、角度各异地散落成拼贴，风暴越乱，它们抖得越厉害 | 粒子风暴，夹杂琥珀色的"警报"粒子 |
| 04 AI 方案 | 轨道图：核心在上方，六个方案像行星一样排在轨道的下半弧 | 风暴平静成圆环，再从核心向每个方案射出数据流 |
| 05 业务成果 | 增长曲线图：六项成果是曲线上的六个标注点 | 一条光线逐点爬升，末端变成箭头 |
| 06 ROI | 发布会式大数字：2x-5x、5x-10x、3 levers 依次在屏幕中央计数，再飞回各自的位置 | 数字落位后，背后升起光柱 |
| 07 给创业者 | 旅程地图：三个里程碑沿上升的路径分布，终点是 "Plan My First AI System" 按钮 | "想法"光点沿路径逐个点亮里程碑，最后落到按钮上 |
| 08 从小处起步 | 技术图纸式的引线标注：三个入门项目从立方体引出 | 粒子搭成一个旋转的立方体（"一个系统"） |
| 结尾 | 标题、按钮、页脚 | 粒子重新拼回 Logo |

**排版**：粗黑体（Instrument Sans）配衬线斜体（Instrument Serif）。每章标题里的关键短语用衬线斜体，形成对比；章节编号、序号和标签用等宽字体。正文段落一出现是暗的，再按阅读速度逐词点亮，像卡拉 OK 字幕一样引导阅读。

原首页的文字全部保留，一字未改。只多了三处衔接文字：开场光点旁的 "Idea"、开场的 "AI execution systems"（取自原页头），以及在痛点和方案两章之间重复了一次原标题里的 "It’s not as hard as you think."。

## 短片之后：其他页面

节与节之间加了几句**新写的旁白**（原页面没有，原文一个字没改），把故事接起来，也由粒子一个字一个字写出来：

| 位置 | 英文 | 中文 |
| --- | --- | --- |
| 短片之后、"关于"之前 | But first, why NaxaStudio exists. | 先说说，纳想为什么存在。 |
| 关于 → AI 方案 | So what does that look like in practice? | 那落到实际，我们能帮你做什么？ |
| AI 方案 → 起步方案 | Not ready for every agent? Start with one practical layer. | 还没准备好用全部助手？可以先从一层开始。 |
| 起步方案 → Demo | Want to see it before you decide? | 做决定之前，先看看它实际怎么工作。 |
| Demo → 案例 | Now, inside a real business. | 放进真实的生意里，是这样的。 |
| 案例 → 业务诊断 | So where do you start? With a review of your business. | 那第一步从哪里开始？先看清你的生意。 |
| 业务诊断 → 联系 | When you are ready, tell us what is slowing you down. | 准备好了，就告诉我们哪里最卡。 |

节与节之间不会突然换题：上一节读完时，所有粒子（包括最后那条发光下划线）先聚成一个亮点，像彗星一样拖着尾巴飞到下一节的片头卡，再在那里绽开成新一节的主视觉，标题跟着翻入。

每一节先是一张整屏的"片头卡"：章节号做成巨大的描边数字在标题后面慢慢漂移，标题逐词翻转入场，右边（手机上是上方）是这一节的粒子主视觉，全亮、一直在动。往下读正文时，主视觉缩小、变暗，退到屏幕边上。

| 顺序 | 内容来自 | 粒子主视觉 | 正文版式 |
| --- | --- | --- | --- |
| 10 | 关于（`about.html`） | Logo 本身，想法的小点不断流进 N（直接接着短片结尾的 Logo） | 宣言式的大段衬线字 |
| 11 | AI 方案（`ai-agents.html`） | 五个 AI 助手从核心一个接一个发射出去，各自进入一条倾斜的轨道；读到哪个助手，哪颗"卫星"就亮起来 | 规格表，五个助手逐行出现 |
| 12 | 起步 AI 方案（`base-ai-agent.html`） | 四层网格一层层落下叠起来，一道光从下往上扫过；读到第几项，第几层就亮 | 四层"第一层工作"像台阶一样错开叠起 |
| 13 | Demo（`demo-center.html`） | 一把锁：先锁着发出琥珀色的光，然后打开，变成一个带播放键的窗口 | 不用方框卡片，而是一条"放映列表"：六个助手名字用大字竖着排，还没轮到的只是一圈描边；轮到哪个，粒子就把它的名字一个字一个字写实，同时在它周围画出一个会流动的光框（光框只在播放这一个的时候出现，粒子走了就消失）；锁着的预览是一条闪烁的"加密"光条，旁边一个圆形播放键，点了弹出原来的解锁表单 |
| 14 | 案例（`cases.html`） | 一团乱糟糟的"问题"挤过一道门（AI），出来变成一条向上的线和箭头；读到问题、方案、改善，对应的那一段就亮 | 每个案例一条"问题 → AI 方案 → 改善"的时间线 |
| 15 | AI 业务诊断（`business-review.html`） | 一个倾斜的雷达在扫，光束转过时六个"机会点"依次亮起，然后连成一张地图（对应"AI 机会地图"）；读到哪个诊断方向，哪个点就亮 | 三步计划、六个诊断方向、三张输出卡片 |
| 16 | 联系（`contact.html`） | 一架纸飞机在空中绕圈飞，身后拖着长长的光尾 | 左边"适合咨询的问题"，右边原来的联系表单 |

各页面的文字（包括 Demo 解锁表单和联系表单）都是从原页面照搬的，一字未改；中文版用的是 `zh-` 开头那几页自己的内容。现有的子页面没有改动。

- 自动滚动像提词器：屏幕上已经能看全的内容就原地读完，下一段不在屏幕里时才往下移；每一段停多久按字数算（英文每秒约 5.6 个词，中文每秒约 11 个字）
- 文字不会一下子全部出来：标题、段落、每一行、每张卡片按阅读顺序一个一个出现。标题逐词翻入；正文、描述这类长一点的字**一个字一个字**淡入（中文每秒约 10 个字，英文每秒约 28 个字母），最前面的几个字带一点光，读完才出下一段
- 每一段出现之前，大约四成的粒子会先飞到它要出现的位置，画出一个和这段内容有关的图标；然后收成一个小光点，停在第一个字前面，像笔一样跟着正在出现的字往前写，身后在这一行下面拖一条淡淡的光；写完落成文字下面一条发光的下划线，再飞去下一段。图标都按那一段具体说的事来选，例如 AI 接待助手是对话气泡（里面的三个点轮流闪），销售跟进是漏斗（线索不断往下掉），营销是喇叭（声波一圈圈往外），研究是放大镜，流程是打勾的清单，案例里的"问题"是一团夹着琥珀色、乱转的粒子，"结果"是向上的增长箭头，预算是一摞硬币，想法是灯泡，第一步是带旗子的路线，工作流程是转动的齿轮；"漏接电话"是正在响的手机，"一忙起来营销就停了"是日历，"重复行政工作"是一摞文件，"还没准备好招齐每个岗位"是三个人（中间那个亮着，代表先上的 AI），"不知道先做哪个"是问号，"支持而不是自动驾驶"和"老板掌控"是方向盘，"踏出第一步并持续推进"是台阶，"从想法到行动到结果"是三个依次点亮的圆，"银行相关经验"是银行，"低成本启动"是火箭，"知识库"是一本书，"AI 机会地图"是地图，"推荐哪个助手"是一个小机器人，"适合咨询的问题"是起点的旗子
- 正在读的那一段是亮的，其他内容变暗；左边一条光条跟着移到正在出现的那一项旁边，光点从上往下走，走完就出下一项
- 标题的每个词从下面翻上来，落位时闪一下光；强调的那句话上有一道光泽来回扫过；正文按阅读速度逐词点亮，点亮的那个词带着光晕，像光标一样往前走
- 整个后半段都不用传统的方框卡片："不知道先做哪个"是一句大号斜体字，起步方案的四层工作是一层层的光线（像地层），诊断输出是带编号的三行，联系表单的输入框只有一条下划线，写的时候会亮
- 页面一动，背景就有动感：星星分几层远近，跟着页面以不同速度移动，滚得快时拉成光线；粒子会被页面带着稍微拖一下再弹回来，移动时拖出更长的尾巴
- 自己滚动（滚轮、触摸板、手指）时自动播放立刻停下，进度条跟着你的位置走；停下不动 7 秒后，播放键外圈走满一圈，从你看到的地方继续往下播。如果是按了暂停键，就一直停着
- 菜单和按钮里指向这些页面的链接（如 `ai-agents.html`、`contact.html`、`ai-agents.html#ai-sales`）会直接滚到本页对应的位置，不再跳走；隐私条款、另一种语言的页面照常打开
- Demo 解锁沿用官网的 `demo-center.js`（原样打包进来）：同样的密码、同样的表单检查，解锁状态和官网的 Demo 页面共用
- 填写联系表单或打开 Demo 表单时，自动播放会停下

## 中文版

`zh.html` 对应 naxastudio.com/zh：内容一字未改，链接都指向中文页面（`zh-business-review.html` 等），右上角 "EN" 回到英文版。针对中文的处理：

- 标题按字逐个出现，正文按阅读速度逐字点亮；借助浏览器自带的中文分词（`Intl.Segmenter`），只在词与词之间换行，不会把"销售""行政"拆到两行
- 强调短语用思源宋体（Noto Serif SC），中文不做斜体
- "实时执行流程"的大字用汉字乱码来解码
- 播放条、按钮、章节名都是中文
- 苹果设备使用本机的苹方字体，其他系统使用思源黑体（Noto Sans SC）

和英文版一样，只多了三处衔接文字：开场光点旁的"想法"（取自原页的"想法 → 行动"）、开场的"AI 执行力系统"（取自原页头），以及在痛点和方案两章之间重复了一次原标题"没有你想象的那么难。"。

## 怎么看

直接用浏览器打开 `index.html` 即可（在 Claude App 或 GitHub 里点开只会显示源代码，要先下载，再用 Safari / Chrome 打开）。所有代码、样式和 Logo 数据都已经打包在这一个文件里。

## 顶部栏和章节目录

顶部不再放一排"首页 / AI 方案 / Demo / 案例 / 关于"的菜单，只留三样：语言切换（EN／中文）、"章节"按钮、"预约业务诊断"按钮（手机上只留语言和章节，预约按钮在章节目录里）。

- 点"章节"会打开一个整屏的目录：左边是短片的 10 章，右边是后面的 7 节（AI 方案下面还列着五个助手）。已经看过的章节是实心的，正在播放的那一章亮着、旁边有一个跳动的点，还没看到的只是描边。点短片的章节就从那一章开始播放，点后面的节就滚到那一节
- 目录里的链接仍然指向原来的子页面地址（`about.html`、`zh-cases.html` 等），搜索引擎照样能找到这些页面；在本页点击时会直接滚到对应位置
- 播放时如果鼠标、手指都没动，2.6 秒后顶部栏淡出，只留一个淡淡的 Logo；一动就回来。按 Esc 或点目录外面的空白处可以关掉目录

## 播放控制

- 底部播放条：播放 / 暂停、上一章 / 下一章；点击或拖动进度条可以跳到任意位置，鼠标悬停会显示章节名
- 点击画面空白处：暂停 / 继续
- 键盘：空格暂停，← → 切换章节，Home / End 跳到开头 / 结尾
- 滚轮（电脑）或上下滑动（手机）：像普通网页一样滚动，自动播放暂停，停下 7 秒后自动继续
- 倍速：1× / 1.5× / 2×
- "Read as page"（按页面阅读）：切换成普通的滚动网页，所有内容一次全部显示。系统开了"减少动态效果"的访客会直接看到这个模式；禁用 JavaScript 时也显示这个版本。
- 网址后面加 `?t=60` 可以从第 60 秒开始播放（`?t=200` 就是在后面的页面部分），加 `?read` 直接进入阅读模式
- 字体从 Google Fonts 加载（Instrument Sans、Instrument Serif），没网时会换成系统字体

## 怎么改

改完 `src/` 下的文件后，运行：

```
node tools/build.js
```

时间都写在 `src/index.html` 和 `src/zh.html` 里：

- 每一章 `<section>` 上的 `data-dur` 是这一章的时长（秒）
- 元素上的 `data-at` 是它在本章第几秒出现，`data-dur` 是出现动画的时长
- `data-out` 是它在第几秒淡出；`data-outm` 也是淡出时间，但只在手机上生效（手机屏幕放不下时，先淡出段落，再让卡片接替它的位置）
- `data-read` 是段落开始逐词点亮的时间，`data-rate` 是每个词的间隔（默认 0.12 秒）
- ROI 数字上的 `data-land` 是它从屏幕中央飞回原位的时间；`data-count` 和 `data-cat` 分别是计数的目标值和开始时间
- `data-forms="storm@0"` 指定粒子在本章第几秒变成哪种形态

短片之后的页面部分（`<div class="tour">` 里）不按秒排，而是按滚动：

- `data-stop` 标记自动滚动的停靠点，停留时间按字数自动算；`data-dwell="12"` 可以手动指定停几秒
- 自动播放时，带 `data-r`、`data-rs`、`data-rr` 的元素按顺序一个一个出现，时间自动按字数排；自己滚动浏览时，它们在滚进屏幕时出现（`data-r` 的数字是延迟几秒）。`data-rs` 让标题逐字出现，`data-rr` 让段落逐词点亮
- `data-icon` 是粒子在这一项出现前画的图标，写在元素自己或它外层的元素上：chat、funnel、megaphone、magnifier、checklist、document、growth、target、shield、envelope、clock、coins、bulb、route、gear、layers、window、storm、logo、question、team、pen、wheel、phone、hourglass、stairs、flow3、shop、bank、rocket、book、map、agent、flag、calendar、papers；`none` 表示不画图标，直接写字（旁白用）
- 旁白是 `<div class="bridge" data-stop><p class="bridge-line" data-r data-icon="none">…</p></div>`，想改措辞直接改这里
- 每个 `<section data-tour>` 上的 `data-label` 是进度条上的章节名，`data-form` 是这一节的粒子形态

例如想让某一章多停留几秒，把这一章的 `data-dur` 调大就行。
